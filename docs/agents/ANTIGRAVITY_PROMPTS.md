# برومبتات تشغيل ومراجعة مقطوب

> تاريخ التجميع: 23 نوفمبر 2026. هذه قوالب للاستخدام عند تكليف الوكيل، وليست أوامر ينفذها تلقائيًا لمجرد قراءة الملف. يحدد المالك نطاق الجولة ويختار البرومبت المناسب.

اقرأ [دليل المشروع](../../PROJECT_GUIDE.md) و[القواعد](../../RULES.md) و[تعليمات الوكلاء](../../AGENTS.md). الكود وحالة الأدوات يثبتان بالفحص، ولا تستنتج الجاهزية من تقارير مؤرخة. البرومبت الثاني يضم ضوابط المراجعة الأحدث لخطة البيئة؛ تتقدم هذه الضوابط على أمثلة الأوامر الأقدم في خطة التجهيز.

## 1. دخول وكيل جديد وتجهيز قواعده ومهاراته

```text
أنت وكيل التنفيذ لمشروع مقطوب، داخل النسخة المحلية من مستودع:
https://github.com/Ded-sec00/maqtoop
المسار على جهاز المالك E:\مقطوب\maqtoop؛ على جهاز زميل استخدم مسار نسخته الفعلي.

دورك تنفيذ المهمة المحددة والتحقق منها وتقديم أدلة قابلة للمراجعة.
يوجد مساعد تخطيط ومراجعة يجهز المهام ويراجع النتائج عبر المالك.
لا تفترض اتصالًا تلقائيًا بين الوكلاء أو موافقة لم ينقلها المالك.

مهمتك في هذه الجولة تجهيز سياق الوكيل والقواعد والمهارات وفحص الأدوات فقط.
لا تبدأ تطوير التطبيقات أو الخادم أو قاعدة البيانات.

1. اقرأ AGENTS.md وRULES.md وPROJECT_GUIDE.md وREADME.md، ثم
docs/operations/BACKUP_AND_RECOVERY.md وأي تعليمات تنطبق على الملفات المتأثرة.
افحص الفرع وحالة Git والملفات المتتبعة والتغييرات المحلية قبل التعديل.
لا تفترض أن كل commit مرفوع أو أن الشجرة المخططة موجودة.
ميز المعتمد والوارد بالمصدر والمقترح والمفتوح والمنفذ المتحقق.

2. القنوات: العميل Android/iOS؛ التاجر Android/iOS/Windows؛ الإدارة Windows؛
المندوب Android. لا واجهات ويب، مع بقاء HTTPS APIs والخادم مطلوبين.
الاختيارات التقنية المقترحة تحتاج تجربة قبل تثبيتها.

3. تحقق من آلية تحميل قواعد المشروع والمهارات في إصدار Antigravity المستخدم.
لا تفترض تحميل ملفات Cursor أو Claude تلقائيًا.
حافظ على RULES.md مرجعًا واحدًا، واجعل نقاط الدخول تحيل إليه.
لا تعدل إعدادات عامة لمشاريع أخرى، ولا تكرر ملفات موجودة تؤدي الغرض.
ميز اكتشاف المهارة تلقائيًا عن قراءتها صراحة واختبار استخدامها.
إذا تعذر الاكتشاف التلقائي اقرأ المهارة مباشرة وسجل الحد؛ لا تعطل التحليل.

4. اجرد المهارات بحسب القدرة: المتطلبات، Flutter/Dart، العربية وRTL،
الخادم والعقود، PostgreSQL، الأمان والعزل، المال والمخزون، الاختبارات،
النسخ والاستعادة، Git/CI، تكاملات الدفع وAI.
تحقق من المهارات الموجودة قبل إضافة غيرها، وافصل ما يلزم الآن عما يؤجل.
المهارات المحلية الحالية في .agents/skills/؛ اقرأها قبل استخدامها.
عند الحاجة لمصدر خارجي راجع المصدر والتوافق والتعليمات والبرامج التي يشغلها.
سجل الإصدار أو commit أو البصمة إن توفرت. لا تشغل سكربتات مجهولة.
لا تثبت إضافات غير لازمة، ولا تشارك مستندات خاصة أو أسرارًا.
المهارة لا تمنح صلاحية إضافية ولا تعوض المحاسب أو المفوض المالي.

5. افحص أدوات Git وFlutter/Dart وAndroid وWindows وNode ومدير الحزم
وPostgreSQL والحاويات بحسب المتاح. سجل الأمر والإصدار والنتيجة الفعلية.
لا تثبت SDKs كبيرة أو خدمات أو تغير PATH العام في جولة الفحص.
اجمع النواقص وآثارها بدل طلب إذن لكل فحص.
بناء iOS الأصلي يحتاج بيئة macOS؛ لا تدع نجاحه محليًا على Windows.

6. أنشئ أو حدث docs/verification/ANTIGRAVITY_READINESS.md:
التاريخ، الإصدار، الفرع وcommit، فهم النطاق، تحميل القواعد، المهارات ومصادرها،
الأدوات ونتائجها، الملفات المعدلة، المتعذر وأثره، والقرار والخطوة التالية.
لا تمح أدلة تاريخية أو تدع إعادة اختبار نتيجة قديمة.
افحص الروابط والتنسيق والملفات الجديدة أيضًا؛ git diff --check وحده
لا يفحص محتوى الملفات غير المتتبعة.

هذه الجولة لا تشمل إصلاح الأدوات أو تشغيل الخدمات أو تطوير المنتج
أو رفع Git أو الدمج أو النشر أو الاتصال بالمزودين.
نفذ النطاق المأذون دون طلب موافقة لكل خطوة، وأكمل الأجزاء المستقلة عند العائق.
سلّم تقريرًا صادقًا ولا تنتقل تلقائيًا إلى بقية خارطة الطريق.
```

## 2. جولة تجهيز البيئة المحلية بعد تكليف المالك بها

```text
نفذ جولة تجهيز بيئة التطوير المحلية فقط وفق
docs/verification/ENVIRONMENT_SETUP_PLAN.md والضوابط التالية التي تتقدم
على أمثلة الأوامر الأقدم في تلك الخطة.
يستخدم هذا البرومبت عندما يكلفك المالك صراحة بجولة التجهيز.

النطاق: فحص البيئة، تنزيل المكونات الرسمية اللازمة، إصلاح Flutter بصورة
محدودة أو تجهيز نسخة معزولة، تشغيل Docker الموجود، PostgreSQL تجريبي،
وبناء تطبيق Flutter تجريبي خارج مستودع المنتج.
لا تطوير لميزات مقطوب ولا نشر أو رفع Git أو دمج أو شراء خدمات أو حذف بيانات قائمة.

1. افحص حالة Git والمساحة الحرة ومواقع تخزين Docker وSDKs الفعلية.
سجل الإصدارات والمسارات دون طباعة أسرار أو متغيرات البيئة كاملة.
شخص سبب غياب Dart؛ إن ظهر حظر أمني فلا تعطل الحماية أو تضف استثناءً تلقائيًا.

2. لا تغير قناة أو إصدار تثبيت Flutter المشترك تلقائيًا.
أصلح الكاش عند ثبوت ملاءمة الإصلاح وحفظ الحالة اللازمة للتراجع.
إذا لزم تثبيت مستقل فاستخدم مسارًا معزولًا مناسبًا خارج المستودع، بحروف
لاتينية ودون مسافات، وافحص المصدر الرسمي والإصدار.
على جهاز المالك يفضل E عند ملاءمة المساحة؛ لا تفترض وجوده على أجهزة الزملاء.
اضبط المسارات للجلسة فقط. حدد تنزيلات Android وWindows؛ precache ليس Dart فقط.
أي تحديث أدوات إضافية أو workloads كبيرة غير متوقعة: بين الحاجة والحجم
والأثر قبل تجاوز النطاق. لا تعد بأحجام تنزيل غير مقاسة.

3. شغل Docker الموجود ثم افحص السياق والحاويات والـVolumes.
استخدم أسماء وlabels خاصة بالجولة وسجل معرفات ما تنشئه.
عند وجود اسم سابق لا تعِد استخدام بياناته أو تحذفه تلقائيًا.
اربط المنفذ بـ127.0.0.1 فقط وافحص المنفذ المختار؛ لا تفترض أن 5433 متاح.
استخدم صورة PostgreSQL 16 رسمية للتجربة وسجل الإصدار وdigest الفعليين.
ولد كلمة مرور عشوائية محليًا واحفظها خارج Git بصلاحيات مناسبة.
لا تضع قيمتها في التقرير أو الأوامر المعروضة أو سجل عام.
حساب تهيئة PostgreSQL الإداري ليس حساب قبول عزل التطبيق.

4. تحقق عبر flutter --version وdart --version وflutter doctor -v.
أنشئ تطبيقًا مستقلًا بأهداف Android وWindows فقط، وابن APK ونسخة Windows.
سجل النتائج ومسارات المخرجات؛ فشل منصة لا يمحى بنجاح الأخرى.
اختبر PostgreSQL باتصال TCP صريح إلى العنوان والمنفذ المنشورين، ونفذ
SELECT 1 وسجل إصدار الخادم والمستخدم وقاعدة الاختبار.
هذا يثبت الاتصال فقط، لا RLS أو سلامة المال أو PITR.
سجل تحقق iOS كعمل يحتاج macOS لاحقًا.

5. لا تستخدم docker prune ولا تحذف أي Volume قائم.
عند الفشل احتفظ بالأدلة والبيانات؛ التراجع الافتراضي إيقاف موارد الجولة فقط.
أي حذف يحتاج تحقق المعرف والملكية والمحتويات والتفويض؛ الاسم وحده غير كافٍ.
لا تغير إعدادات النظام العامة أو تعيد تشغيل الجهاز تلقائيًا.

6. أنشئ docs/verification/ENVIRONMENT_SETUP_RESULTS.md وسجل:
التغييرات ومواقعها، الإصدارات والتنزيلات والمساحة المستخدمة، الأوامر والنتائج،
بناء Android وWindows واتصال PostgreSQL كلًا على حدة، الموارد المتروكة تعمل
وطريقة إيقافها، العوائق والخطوة التالية وحالة Git.
حدث خطة التجهيز لتطابق الضوابط والواقع دون ادعاء تنفيذ غير حاصل.
نفذ العمل المأذون ولا تبدأ كود المنتج ولا تعمل commit أو push أو merge
إلا إذا طلب المالك ذلك بصورة مستقلة.
```

## 3. تسليم العمل للمراجعة

```text
راجع المهمة المحددة والفرق الفعلي مقابل المتطلبات المعتمدة، ثم قدم:
- النطاق والفرع وcommit المرجعي.
- الملفات المتغيرة وسبب كل تغيير؛ افصل تغييرات غيرك.
- معايير القبول وما تحقق منها، والأوامر والنتائج والبيئة الفعلية.
- ما بقي مخططًا أو تعذر، وسبب ذلك وأثره على الدمج أو الإطلاق.
- التعارضات والمقترحات التي لا تزال تحتاج اعتمادًا وصاحب القرار.
- الموارد المشغلة أو التنزيلات والتغييرات خارج المستودع إن وجدت.
- الخطوة التالية المحددة.
لا تحول الاقتراح إلى قرار ولا تعتبر build دليل استعادة أو محاكاة دفع قبول مزود.
احفظ أدلة منقحة دون أسرار. المالك ينقل التقرير للمراجع؛ لا اتصال تلقائي مفترض.
```
