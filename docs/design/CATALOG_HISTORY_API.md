# عقد سجل نسخ المسودة والمقارنة

28 نوفمبر2026 — R03 والمرحلةA، قراءة خاصة للإدارة ولصاحب المسودة المخول. لا نشر أو بيع أو استرجاع نسخة قديمة كعملية تعديل، ولا واجهة ويب.

## التثبيت والتوافق

تثبت catalog_history.sql مرة واحدة بعد merchant_draft_list.sql. تضيف purchase_api.catalog_history(text,jsonb,text) وقارئcatalog.revision_json(uuid,integer,boolean) الخاصSTABLE، دون تغيير جداول أو محتوى تاريخي. يمنح المشغل EXECUTE لدالةAPI فقط إلىLOGIN التاجر والإدارة المحددين، بالإضافة لصلاحيات الحسابات القائمة:

```sql
grant execute on function purchase_api.catalog_history(text,jsonb,text) to example_merchant_login;
grant execute on function purchase_api.catalog_history(text,jsonb,text) to example_admin_login;
```

الأسماء مثال وليست أدوارًا تنشئها الترحيلة. لاPUBLIC EXECUTE ولا منح مباشر لجداولcatalog أو القارئ الخاص. حتى مع منحEXECUTE لدور آخر عمدًا ترفض الدالة جلسته. يعمل الامتداد خلفcatalog.enabled القائم؛ لا تغييرات عقد العميل أو المندوب، ويمكن لتطبيق التاجر Android/iOS/Windows والإدارةWindows استهلاكه لاحقًا. لا شاشات منفذة في هذا الطلب.

## المسارات

الجذر للتاجر /v1/merchant/catalog/submissions/{id}، وللإدارة /v1/admin/catalog/submissions/{id}. كل الطلباتGET معBearer صالح؛ لا حاجة إلىIdempotency-Key للقراءة. id هوUUID المسودة. لا دور أو منشأة أو مالك يرسل من العميل.

| المسار بعد الجذر | الطلب والنتيجة |
|---|---|
| /revisions | قائمة بيانات النسخ: revision،createdAt،review أوnull؛ لا محتوى كامل. المعاملان الاختياريانlimit من1 إلى100 افتراضي50، وcursor رقم آخرrevision موجب |
| /revisions/{revision} | نسخة محددة، بكاملcontent المحفوظ ووقت الحفظ ومراجعتها الفعلية |
| /compare?from=1&to=2 | النسختان بكامل المحتوى ومراجعاتهما، والتغييرات والصور المضافة والمحذوفة |

revision وfrom وto وcursor أعداد صحيحة موجبة حتى999999999. رقمrevision مختلف عنversion للعملية؛ مثلًا الإرسال للمراجعة يغيرversion دون إنشاء محتوى جديد. المقارنة تسمح بالاتجاهين وبالنسخة نفسها، التي ترجعchanges وصورًا مضافة/محذوفة فارغة. لا معاملات زائدة أو مكررة، ولا جسمGET. عمليات الكتابة على هذه المسارات غير متاحة.

تضم كل استجابةsubmissionId وbranchId، وversion وcurrentRevision وstate الحالية، وpublicationEnabled=false. هذه الحالة الحالية تخص المسودة، ولا تدعي حالة تاريخية لم تسجل لكل نسخة. review إن وجدت تضمdecision وreason وdecidedAt فقط؛ لا أسماءLOGIN داخلية. الأوقاتUTC بدقة6 خانات كسرية.

القائمة مرتبة برقمrevision تصاعديًا، وتعيدitems/hasMore/nextCursor. nextCursor نص رقم آخرنسخة أوnull، وليس اعتماد وصول؛ يمكن تغيير موضعه لكن لا يتجاوز ملكية المسودة والتفويض. cursor بعد نهاية التاريخ يعيد قائمة فارغة. كل صفحة قراءة مستقلة وقد ترى نسخًا أضيفت بعد الصفحة السابقة.

## شكل المقارنة

from وto هماDTO النسختين، كل منهما revision/createdAt/review/content. تقارنchanges حقولcontent فقط، بترتيب اسم الحقل، مثل:

```json
{
  "field": "model",
  "before": "Model A",
  "after": "Model B",
  "beforePresent": true,
  "afterPresent": true
}
```

beforePresent/afterPresent يميزان غياب الحقل عن قيمتهnull. التغيير يقارن القيمةJSON المحفوظة كاملة؛ لا يجمع الفروق المالية أو يقرر سعرًا أو ضمانًا.

media.added وmedia.removed مصفوفتا معرفات الصور الخاصة المضافة والمحذوفة بحسب اتجاه المقارنة. ترتيب الصور المتغير يظهر فيbefore/after لحقلmediaAssetIds، ولو لم توجد إضافات أو حذف. لاbytes أوروابط عامة في التاريخ؛ تنزيل الصورة يظل من مسار الصور الخاص الذي يعيد فحص الصلاحية.

## الصلاحيات والأقفال

مساراتmerchant تتطلب دورmerchant الحالي وcreated_by صاحب الجلسة وmerchant_id المطابق وفرعًا مخولًا حاليًا. مستخدم آخر في نفس المنشأة والتاجر الآخر مرفوضان. مساراتadmin تتطلبadmin الحالي، وتسمح له بقراءة السجل دون تفويض فرع تاجر. العميل والمندوب والخدمة مرفوضون، ولا تصلح جلسةadmin لمسارmerchant أو العكس.

يقفل الخادم صف المسودةSHARE، ثم يتحقق من تفويض الفرع ويقفله، ثم يعيد فحص الجلسة بعد الانتظار. سحب الفرع المثبت قبل استئناف قراءة التاجر يرفض403 لجميع مسارات التاريخ، حتى النسخ القديمة. إبطال الجلسة أثناء الانتظار يرفض401. فحص المالك والمنشأة يعاد بهوية الجلسة الحالية أيضًا.

تبقى الأقفال حتىCOMMIT. إذا أخذت قراءة مخولة القفل أولًا، ينتظر الكاتب أو الساحب ولا تلغى قراءة مثبتة بأثر رجعي. القارئSTABLE والتاريخ غير القابل للتعديل وقفل المسودة يمنعون خلط المحتوى التاريخي أو بيانات المراجعة مع نسخة جديدة؛ الكاتبHTTP المتزامن ينتظر ثم ينشئ نسخته التالية.

## الأخطاء والرجوع

400/INVALID_INPUT للمعرف أو الأرقام أو الاستعلام غير الصحيح،401/INVALID_SESSION للجلسة الملغاة،403/ACCESS_DENIED للدور أو المالك أو الفرع،404/NOT_FOUND للمسودة أو النسخة المفقودة بعد التحقق المناسب. الطلب على سجل موجود غير مخول يرفض قبل قراءة أرقام نسخه. لا تفاصيلSQL أو بيانات اتصال في الأخطاء.

الترحيلة ذرية ويختبر فشل قبلCOMMIT يحذف إضافاتها ويحفظ البيانات السابقة. الرجوع إلى خادم سابق يوقف المسارات الجديدة، مع إبقاء ترحيلات وأحكام صلاحيات الفروع والنشر القائمة. لا يسترجعschema قديم فوق بيانات أحدث. لا ترحيل إنتاج أو إثبات نسخ/PITR في هذه المهمة؛ مرجعها BACKUP_AND_RECOVERY.

approve يظل409/CATALOG_POLICY_NOT_CONFIGURED، وقائمة العميل فارغة. لاSKU أوstock أوoffer أوأهلية أوتحصيل أومستحق أو قيد ينتج من هذه القراءات، ولا اعتماد سعر أوضمان أو7291.
