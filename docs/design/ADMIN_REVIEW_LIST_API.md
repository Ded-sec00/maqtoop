# عقد قائمة مراجعة الإدارة الموسعة

28 نوفمبر2026 — R03 والمرحلةA، قراءة داخلية لتطبيق الإدارةWindows فقط. لا واجهة ويب أو نشر أو بيع أو اعتماد سياسة سعر/ضمان/7291.

## التثبيت والتوافق

تثبتadmin_review_list.sql مرة واحدة بعدcatalog_history.sql. تضيف فهرس ترتيب ودالةpurchase_api.catalog_review_list(jsonb,text) وقارئcatalog.review_submission_json(uuid) الخاصSTABLE. لا تغيير لبيانات أو صلاحيات جداول التطبيق، ولاPUBLIC EXECUTE. يمنح المشغل LOGIN الإدارة فقط:

```sql
grant execute on function purchase_api.catalog_review_list(jsonb,text) to example_admin_login;
```

example_admin_login اسم توضيحي وليس دورًا تنشئه الترحيلة؛ تلزمه صلاحيات الحسابات القائمة. فحص الدور الحالي داخلSQL يمنع الأدوار الأخرى حتى إذا منحها المشغلEXECUTE خطأ. المسار خلفcatalog.enabled القائم.

GET /v1/admin/catalog/submissions يبقى افتراضيًاpending_review، وبحد100 لكل صفحة، وcursor UUID القديم. الحقول الحالية مستمرة وتضافmerchantId/merchantName/createdAt وpublicationEnabled=false. لا تغيير لمسارات التاجر والعميل والمندوب أو شاشات أصلية منفذة. دالةcatalog_read(review/list) القديمة تبقى قراءةSQL الأساسية السابقة؛ يستخدمHTTP الموسع الدالة الجديدة. الرجوع إلى خادم سابق يعيد القائمة الأساسية السابقة دون حذف ترحيلات التفويض أو تاريخ البيانات.

## المعاملات

Bearer مدير صالح إلزامي. جميع المعاملات اختيارية، ولا جسمGET أو مفتاح تكرار مطلوب:

| المعامل | القاعدة |
|---|---|
| q | بحث جزئي حرفي فيbrand أوmodel وفقlower فيPostgreSQL، حتى100حرف بعد التشذيب. الفراغ بلا بحث، و% و_ والشرطة العكسية حروف عادية. يمنعNUL |
| merchantId | bigint موجب كنص، مستخرج مقابل سجل التاجر الموجود في القاعدة |
| branchId | bigint موجب كنص؛ يجب أن يوجد ويتبعmerchantId إذا حدد الاثنان |
| state | draft/pending_review/changes_requested/rejected/withdrawn، أوall؛ الافتراضيpending_review |
| limit | عدد صحيح من1 إلى100، الافتراضي100 |
| cursor | UUID آخرسجل في الصفحة السابقة |

مثال: /v1/admin/catalog/submissions?merchantId=1&branchId=2&state=changes_requested&q=Samsung&limit=20

الأرقام نصوص فيمعرفات التاجر والفرع لمنع فقد دقةbigint في التطبيقات، ولا يقبل رقم يبدأ بصفر أو0 أوعدد يتجاوزbigint. لا معاملات زائدة أو مكررة، مثلrole/login. state=all يعرض الحالات الخمس الحالية، ولا توجدapproved في هذه الشريحة.

## النتيجة والصفحات

استجابة200 فيهاitems/hasMore/nextCursor وpublicationEnabled=false. كلitem يحملDTO المسودة الحالي: المحتوى والنسخة ورقمrevision والحالة ومراجعاتها والفرع وmissingDependencies، إضافة إلىmerchantId/merchantName من القاعدة وcreatedAt بتوقيتUTC ودقة6خانات كسرية. لاLOGIN داخلي أوbytes صور أو رابط نشر عام. معلومات التاجر المضافة خاصة بهذا المسار الإداري؛ لا تنتقل إلى قائمة العميل.

تصفى النتائج قبل حدالصفحة، وترتبcreated_at ثمid تصاعديًا. nextCursor هوUUID آخرنتيجة أوnull. المؤشر موضع، وليس اعتماد وصول أو توقيعًا أو ربطًا بالتصفية. عند تغيير التصفية يبدأ العميل بلاcursor؛ تمرير مؤشر مع تصفية مختلفة مسموح لكنه يستمر بعد موضعه، ولا يعد بدء بحث جديد.

يقرأ سجل الارتكاز ولو تركpending_review، فتواصل الصفحة التالية دون فقد بقية الطابور. سجل ارتكاز مفقود404؛ لا حذف للمسودات عبر هذه الشريحة. cursor مزور لا يجاوز فحصadmin أو مرشحاتSQL. الصفحات ليستsnapshot ثابتة بين الطلبات؛ قد تتغير العضوية عند تعديل الحالات أو المحتوى. داخل الصفحة الواحدة تستخدم التصفية وقارئDTO الثابت لقطة استعلام واحدة، فلا تظهر حالة أو محتوى أحدث لا يطابقان التصفية.

منid النتيجة يمكن استخداممساراتadmin الحالية لقراءة التفاصيل وrevisions وcompare؛ لا صلاحية أو رابط نشر إضافي ينتج عن القائمة.

## الأقفال والجلسة

يفحصSQL جلسةadmin أولًا دون الاحتفاظ بقفلها، ثم يقفلSHARE بيانات التاجر والفرع المحددين وسجل المؤشر إنوجد، لأغراض التحقق وموضع الصفحة. بعد انتظار هذه الأقفال يعيد فحص الجلسة الحالية مقفلة قبل قراءة النتائج. لا تعتمد الصلاحية على دور أوهوية منالاستعلام.

إذا أُلغيت الجلسة بـlogout-all أوتغيير كلمة المرور أوإيقاف الحساب وإعادة تفعيله بينما القراءة تنتظر تلك الأقفال، ترفضالجلسة القديمة401 دونitems، وتنجح جلسة دخولجديدة. أما إذا اكتمل التحقق المقفل أولًا، ينتظر الإلغاء نهاية القراءة؛ لا إلغاء بأثررجعي لقراءة مخولة مثبتة.

لا قفل استعراضي خاص بالاختبار؛ الأقفال على سجلات فعلية مستخدمة في التصفية أو المؤشر. لا تغييرGET لمسودة أوقرار أوصورة أوتدقيق محتوى أو مخزون أو مال. صور النتائج تبقى عبرالمسار الخاص الذي يفحصالصلاحية.

## الأخطاء والترحيل

400/INVALID_INPUT للمعاملات والأرقام والمؤشر غيرالصحيح أوعدم انتماء الفرع للتاجر المحدد.404/NOT_FOUND للتاجر أوالفرع أوالمؤشر المفقود بعد الفحص المناسب.401/INVALID_SESSION للجلسة الملغاة، و403/ACCESS_DENIED للدور غيرالإداري. لاSQL أوبيانات اتصال في الأخطاء.

الترحيلة ذرية ويختبر خطأقبلCOMMIT يحذف إضافاتها ويحفظ البيانات السابقة. لا ترحيل إنتاج أواثبات نسخ/PITR هنا؛ مرجع القبول BACKUP_AND_RECOVERY. تبقىapprove مرفوضة409/CATALOG_POLICY_NOT_CONFIGURED وقائمة العميل فارغة، دونSKU أوstock أوoffer أوتحصيل أو مستحق أوقيد جديد.
