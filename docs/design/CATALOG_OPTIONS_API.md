# مصادر خيارات الفروع والتجار — المرحلة A

28 نوفمبر2026 — R03 وواجهات التاجر Android/iOS/Windows والإدارة Windows فقط. مصادر قراءة مستقلة عن وجود مسودات؛ لا واجهة ويب أو إنشاء تاجر/فرع أو منح تفويض عبر هذه المسارات.

## المسارات والصلاحيات

| GET | الجلسة الحالية | البيانات |
|---|---|---|
| /v1/merchant/catalog/branches | merchant | فروع صاحب الجلسة ذات التفويض النشط والمنتمية إلى منشأته |
| /v1/admin/catalog/merchants | admin | معرف واسم كل تاجر أعمال من purchase.merchant، ولو لم يكن له حساب أو مسودات |
| /v1/admin/catalog/merchants/{merchantId}/branches | admin | فروع التاجر المحدد، ولو لم تكن مسندة لحساب أو تحتوي مسودة |

Bearer إلزامي. GET فقط، بلا جسم أو Idempotency-Key مطلوب. هذه المسارات خلف catalog.enabled القائم. الدور والهوية من الجلسة والقاعدة؛ دور الإدارة لا يفتح مسار التاجر والعكس. العميل والمندوب والخدمة مرفوضون. مصدر الخيارات لا يمنح صلاحية كتابة جديدة؛ حفظ المسودة يعيد فحص الفرع والجلسة كالمعتاد.

## المعاملات والنتائج

المعاملات الاختيارية فقط: q نص حتى100 حرف بعد التشذيب بلاNUL، وlimit صحيح1–100 افتراضي50، وcursor آخرمعرف موجب كنصbigint حتى9223372036854775807. ترفض المعاملات الزائدة أو المكررة. merchantId في مسار فروع الإدارة موجب بالصيغة نفسها، وليس accountId أوidentityId. لا يمرر merchantId أوbranchId أوrole في الاستعلام.

البحث جزئي حرفي بحسبlower/strpos: اسم التاجر من القاعدة، وفي الفروع التسمية المشتقة «الفرع {branchId}». الرموز % و_ والشرطة العكسية لا تعمل كأنماط. لا اسم فعلي للفرع في schema الحالية؛ displayName تسمية عرض مولدة وليست اسمًا مسجلًا. لا تغيير schema أو API تحرير أسماء في هذه المهمة.

```json
{
  "items": [{"branchId":"2","displayName":"الفرع 2"}],
  "hasMore":false,"nextCursor":null,"publicationEnabled":false
}
```

عنصر قائمة التجار: {merchantId,merchantName}. عنصر فروع الإدارة: {branchId,displayName,merchantId}. عنصر التاجر لا يحتوي هوية تاجر آخر أو أسماء حسابات أوlogin أو مال أو تكاليف أو معدلات عمولة. جميع المعرفات نصوص حتى عند تجاوز دقة أرقامJavaScript.

الترتيب رقمي تصاعدي بالمعرف، واستئنافبعدcursor، دونOFFSET أوtotalCount. cursor موضع وليس تفويضًا أو مؤشرًا موقعًا أو مرتبطًا بالبحث؛ يمكن أن يكون معرفًا غير موجود. إذا تغير البحث أو التاجر أو حجم الصفحة، تبدأ الواجهة بلاcursor. لا يظهر فرع غير مخول بتغيير المؤشر. الصفحات مستقلة وقد تتغير عضويتها بين الطلبات؛ ليست لقطة تاريخية واحدة.

التاجر الموجود بلا فروع يرجع200 وقائمة فارغة، والتاجر غير الموجود في مسار فروع الإدارة404. تاجر بلا تفويض نشط يرجع200 وقائمة فارغة. لا تستنتج الواجهة من غياب نتائج البحث أنه لا توجد فروع أصلًا.

## الأقفال وإلغاء الصلاحية

تتحقق الدالة من الدور أولًا دون الاحتفاظ بصلاحية قديمة عبر الانتظار. لفروع التاجر: تقفلSHARE بيانات الفروع المطابقة من منشأته بترتيب المعرف، ثم تفحص وتقفل كل تفويضنشط حالي. تحفظ فقط المعرفات التي نجح قفل تفويضها. فحص المنشأة في القراءة النهائية يمنع تفويضًا خاطئًا لفرع منشأة أخرى.

تعدد الفروع المطابقة يقفلها قبلحدالصفحة كيلا يؤدي سحب مرشح أثناء الانتظار إلى قطع الصفحة أوإخفاء بقيتها خطأ. هذا اختيار محدود للنسخة التجريبية، لا ادعاء أداء إنتاج عند آلاف الفروع؛ ميزانية الأقفال تحتاج قياسًا قبل الإنتاج.

إذا كان قرارسحب عبرHTTP قد كتب التفويض ولميثبت بعد، تنتظر القراءة قفلصف التفويض، ثم تستبعد الفرع إذا ثبت السحب. إذا ثبتت القراءة المخولة أولًا ينتظر السحبنهايتها؛ لا إلغاء بأثررجعي. المنح الجديد غير المثبت لايظهر، ويظهر في طلب لاحق بعدCOMMIT. السحب ثم إعادةالمنح الصريحة يستخدم الصلاحية الحالية؛ ليسepoch لإلغاء كل الطلبات عبر دورةسحب/منح.

قائمة التجار تقفل صفوف الصفحة مع مرشحextraواحد؛ فروعالإدارة تقفل التاجرالأب وصفوففروع الصفحة. تعيد المسارات الثلاثة فحص الجلسة مقفلة بعدجميع الانتظارات قبل تركيب النتيجة. logout-all وتغييركلمةالمرور والإيقاف/إعادةالتفعيل أثناء الانتظار ترفضالجلسة القديمة401 بلاitems؛ دخولجديد ينجح. الصلاحية المقفلة أولًا تبقى حتىنهاية المعاملة.

هذهGET لا تكتب تفويضًا أوcatalog أوتدقيقمحتوى أوrequest_result أو بياناتشراء. أسماءالتجار وحقولالنتيجة من استعلامالقراءة نفسه؛ لا إعادةتركيب ببياناتعميل أوقارئVOLATILE منفصل.
