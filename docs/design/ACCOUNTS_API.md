# الحسابات وتسجيل الدخول — 26 نوفمبر 2026

النطاق حسابات الإدارة والعملاء والتجار والمناديب فوق هوية first-purchase الحالية. تُنفذ الترحيلة [accounts.sql](../../db/first_purchase/accounts.sql) مرة واحدة بعد schema.sql وsecurity.sql وhttp.sql. تربط الحساب بهوية عمل موجودة مسبقًا، والصلاحية مشتقة من تلك الهوية على الخادم.

## العقد

| المسار | الجلسة المطلوبة | النتيجة |
|---|---|---|
| POST /v1/auth/login | معرّف دخول وكلمة مرور | accessToken وexpiresAt وملف مستخدم آمن |
| GET /v1/auth/me | جلسة نشطة | accountId وloginName وrole وidentityId |
| POST /v1/auth/logout | جلسة نشطة | إلغاء الجلسة الحالية |
| POST /v1/auth/logout-all | جلسة نشطة | إبطال الجلسات الحالية بإصدار حساب جديد |
| POST /v1/auth/password | جلسة نشطة وcurrentPassword وnewPassword | تغيير البصمة وإبطال الجلسات السابقة |
| GET /v1/account-identities | إدارة | الهويات المهيأة المتاحة مع أدوارها ومعرفاتها العامة |
| GET /v1/accounts | إدارة | حسابات وبيانات تعريفها وحالتها |
| POST /v1/accounts | إدارة | إنشاء حساب باسم دخول وكلمة مرور لهوية identityId محددة |
| POST /v1/accounts/{id}/disable | إدارة | إيقاف الحساب وإبطال جلساته |
| POST /v1/accounts/{id}/enable | إدارة | إعادة تفعيل الحساب مع بقاء الجلسات السابقة مبطلة |

معرف الدخول نص بطول 3–80 من الحروف اللاتينية والأرقام والرموز . _ + @ -، ويُحفظ بحروف صغيرة بعد حذف الفراغات الطرفية. يسمح ذلك بمعرف مختار أو هاتف أو بريد بصيغة متوافقة. كلمة المرور من 12 إلى 128 حرفًا. هذه حدود تنفيذ أولية قابلة للمراجعة.

تشتق بصمة كلمة المرور بـscrypt مع ملح عشوائي مستقل لكل حساب، وتبقى البصمة في مخزن محمي. لا تظهر في HTTP أو سجل التدقيق. يصدر الدخول رمز جلسة عشوائيًا، وتُحفظ SHA-256 للرمز فقط. مدة الجلسة الحالية 8 ساعات، وحد محاولة الدخول 5 خلال 15 دقيقة لكل معرّف دخول وعنوان اتصال. يحد الخادم من عدد عمليات اشتقاق البصمة المتزامنة.

تعاد 401 لبيانات دخول غير صحيحة دون تحديد وجود الحساب، و429 عند بلوغ حد المحاولات. رفض الدور 403. الحقول الإضافية مثل role في إنشاء الحساب تُرفض. تستمد عمليات الشراء هوية قاعدة البيانات من الجلسة الموثقة.

## ربط هوية العمل

بيانات الاتصال في إعداد الخادم تربط كل LOGIN محدود بهوية عميل أو تاجر أو مندوب أو إدارة. تربط الحسابات الجديدة التي تنشئها الإدارة بالهويات المهيأة، ويظل تجهيز المنشأة والفرع والمندوب وهوية اتصالهما من مهام إدارة البنية. لا يملك مستخدم منح نفسه دورًا أو تعيين هوية منشأة من طلب الشراء.

تحفظ http_session مع account_id وإصدار كلمة المرور. يفحص authenticate وhttp_actor حالة الحساب وإصداره في كل طلب، بما فيه إعادة نتيجة Idempotency سابقة. تغيير كلمة المرور وإيقاف الحساب والخروج من الجميع يبطل الإصدارات السابقة، وتصدر الجلسة الجديدة بعد إعادة فحص الحساب تحت القفل. لا يُعاد تفعيل جلسة قديمة عند إعادة تفعيل حسابه.

تلغي الترحيلة الجلسات البشرية القديمة غير المرتبطة بحساب، وتحتفظ بجلسات خدمة الدفع الآلية. حساب الخدمة الآلي منفصل عن حساب دخول بشري. إنشاء أو إيقاف حساب المستخدم الحالي من واجهة الإدارة يرفضه التنفيذ لتفادي قطع الحساب الإداري لنفسه.

## تجهيز أول حساب

يوفر [provision-account.mjs](../../backend/provision-account.mjs) تجهيزًا إداريًا موثوقًا. يقرأ ملف JSON خاصًا خارج المستودع يحتوي identityId وloginName وpassword، ويتصل بهوية تشغيل عبر PGHOST وPGPORT وPGDATABASE وPGUSER وPGPASSWORD. يمكن تجهيز أول أدمن لهوية إدارية أنشأها مشغل القاعدة، ثم إنشاء بقية الحسابات عبر HTTP.

تُشغّل الأداة من جذر المشروع باستخدام node backend/provision-account.mjs ثم مسار الملف الخاص. تكتب بصمة كلمة المرور وتُخرج accountId فقط. تحفظ ملفات الإعداد والرموز وبيانات الاتصال خارج Git.
