# PostgreSQL CI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Run the existing PostgreSQL/HTTP suite on GitHub, reject failed or empty runs, and retain evidence.
**Architecture:** An Ubuntu24.04 runner with Node22 installs both locked dependency sets, runs guard tests, then invokes a fail-closed wrapper around the existing suite. The wrapper deletes stale evidence, requires child exit0 and a complete nonempty report, and enforces the current77-case baseline. The workflow runs for every push and pull request without path filters. Branch protection is documented and remains a user-admin step. Initial Windows-hosted execution was rejected by PostgreSQL because runneradmin has administrative privileges; Ubuntu uses a non-root runner.
**Tech Stack:** GitHub Actions, Node built-in test runner, PostgreSQL16.16 from the existing embedded package.
**Spec:** User request in this chat, task08 in EXECUTION_PLAN.md, R03 and RULES.md verification requirements.

## Review focus

Old committed results must never satisfy CI. Process failure must fail even if JSON claims success. Empty or incomplete results must fail even with process exit0. Artifacts/summary cannot turn a failed job green. No secrets, provider calls, deployments, or repository-rule changes.
