# تنفيذ قائمة مسودات التاجر

النطاق المفوض: R03 والمرحلةA، GET لقائمة المسودات مع البحث والتصفية والصفحات، واختبار HTTP/PostgreSQL. لا نشر أو بيع أو تغيير سعر/ضمان/7291. الأساس main عندfb21715، والتنفيذ المحلي على codex/merchant-draft-list.

## التصميم

- GET /v1/merchant/catalog/submissions خلف catalog.enabled القائم. merchant فقط، created_by من الجلسة، والمنشأة وفروعها من القاعدة. حساب آخر في المنشأة نفسها لا يرى مسودات زميله.
- المعاملات الاختيارية: branchId، state (الحالات الخمس الحالية)، q للبحث الحرفي غير الحساس لحالة الأحرف في brand/model، limit من1 إلى100 افتراضي50، cursor. يرفض أي معامل إضافي أو مكرر. q حتى100حرف بعد التشذيب.
- الترتيب created_at ثمid تصاعديًا. مؤشر مستقل يحمل الموضع الدقيق وربطًا بالحساب ومعاملات البحث؛ ليس وسيلة تفويض. لا يعتمد على بقاء سجل الصفحة السابقة أو صلاحية فرعه. تعديل التصفية أو الحساب يتطلب بدء صفحات جديدة.
- القائمة دون branchId تخفي الفروع غير المخولة وتعيد قائمة فارغة إذا لم يبق تفويض. طلب فرع بعينه دون تفويض403. لا تسرب معرفات أو عدد سجلات الفروع المخفية.
- يقفل SQL تفويضات القراءة SHARE بترتيب الفروع، ويحفظ مجموعة الفروع المقفلة، ثم يعيد فحص جلسة التاجر بعد الانتظار، ثم يقرأ سجلاته ضمن تلك المجموعة. يمنع ظهور تفويض جديد غير مقفل بين الفحص والقراءة. تظل الأقفال حتى COMMIT؛ السحب لا يلغي قراءة مثبتة بأثر رجعي.
- الصفحات قراءة للحالة الحالية وليست snapshot تاريخية: تغير حالة مسودة أثناء التصفح قد يغير عضويتها. لا OFFSET، ولا اعتماد معرف cursor وحده لتحديد صاحب البيانات.
- ترحيلة إضافية merchant_draft_list.sql بعد branch_permissions.sql: دالة محدودة SECURITY DEFINER وفهرس، بلا تغيير بيانات. لا PUBLIC EXECUTE ولا وصول مباشر لجداول التطبيق. rollback للترحيلة الفاشلة مختبر في قاعدة معزولة؛ لا ادعاء نسخ/PITR.

## خطوات التنفيذ والتحقق

- [x] اختبار HTTP جديد merchant-drafts-list-http يشاهد404 قبل إضافة المسار.
- [x] إضافة catalog-list.mjs لتحقق المعاملات والمؤشر، وربطه بمسار القراءة ودالة merchant_catalog_list(jsonb,text).
- [x] ترحيلة دالة القائمة والفهرس، مع حفظ بيانات الشراء والتفويضات في فشلها ونجاحها، ومنح EXECUTE المحدد في fixture فقط.
- [x] التحقق من التاجر الآخر وزميل المنشأة، كل الحالات والتصفية والبحث العربي والرموز الحرفية، وقائمة تتجاوز100 سجل بترتيب متعادل الوقت، والمؤشرات غير الصالحة والمتغيرة.
- [x] سحب الفرع عبر HTTP وهو يمسك القفل وطلب القائمة ينتظره؛ النتيجة تخفي فرعه، والطلب المحدد للفرع403. إبطال جلسة التاجر أثناء انتظار القائمة يرفض401. لا أثر على المسودات أو المخزون أو القيود.
- [x] إعادة تشغيل المجموعة كاملة عبر حارس CI، ومراجعة مستقلة للفرع، وتوثيق العقد والنتيجة. لا commit/push/merge في طلب التنفيذ المحلي هذا.
