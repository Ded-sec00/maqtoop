# تنفيذ قائمة مراجعة الإدارة

النطاق R03 والمرحلةA؛ تنفيذ محلي علىcodex/admin-review-list منmain/2c0fa1d. لا نشر أو بيع أو اعتماد سعر/ضمان/7291.

## التصميم

- توسيع GET /v1/admin/catalog/submissions خلفcatalog.enabled، للإدارة الحالية فقط. يبقى الافتراضيpending_review وحد100 ومؤشرUUID القديم متوافقًا.
- معاملات اختياريةq للبحث الجزئي الحرفي غير الحساس لحالة الأحرف فيbrand/model حتى100حرف بعد التشذيب، وmerchantId/branchId نصbigint موجب، وstate للحالات الخمس أوall، وlimit من1 إلى100، وcursor UUID. لا معاملات زائدة أو مكررة.
- التاجر والفرع من القاعدة؛ المفقود404، وعدم تطابق الفرع مع التاجر المحدد400. لا اختيار دور أو هوية جلسة من العميل.
- الترتيبcreated_at/id تصاعديًا، والمرشحون يصفون قبلحدالصفحة. المؤشر موضع وليس اعتمادًا، ويقرأ سجل الارتكاز ولو تغيرت حالته؛ تغيير التصفية يستلزم بدء التصفح بلاcursor ولا يعد التصفحsnapshot ثابتة بين الطلبات.
- الدالة الجديدةpurchase_api.catalog_review_list(jsonb,text) تتحقق منadmin دون قفل أولًا، ثم تقفل بيانات التاجر/الفرع المحددين وسجل المؤشرSHARE إن وجدت، ثم تعيد فحص الجلسة مقفلة بعد الانتظار. عملياتlogout-all/تغيير كلمة المرور/إيقاف وإعادة تفعيل الحساب أثناء الانتظار تجعل الجلسة القديمة401. لا قفل وهمي لمجرد الاختبار.
- قارئDTO خاصSTABLE يركب القارئ الثابت القائم وmerchantId/merchantName/createdAt للإدارة فقط. المحتوى والحالة والمراجعات وبيانات التاجر من لقطة الاستعلام نفسها، دون تغيير قارئ الكتابة أو مسارات التاجر/العميل.
- ترحيلةadmin_review_list.sql بعدcatalog_history.sql تضيف دالةAPI وقارئًا خاصًا وفهرسًا؛ لا تغيير بيانات أوPUBLIC EXECUTE. الاستعلام القديمcatalog_read(review/list) يبقى واجهةSQL الأساسية القديمة، ويستخدمHTTP الموسع الدالة الجديدة.
