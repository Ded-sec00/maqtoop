# خطة تهيئة بيئة التطوير والتحقق الهندسي — مقطوب

> **تاريخ الوثيقة**: 23 نوفمبر 2026\
> **الحالة**: خطة تنفيذية مقترحة للجولة التالية (تمهيد للمهمة 03 وBK02).\
> **الالتزام بالحدود**: **هذه الوثيقة خطة تخطيطية فقط**؛ لا تتضمن أي تنزيل لأدوات أو تشغيل خدمات أو تعديل إعدادات عامة في الجولة الحالية.

---

## 1. الهدف والنطاق

تهدف هذه الخطة إلى توفير مسار عمل آمن ومنضبط لإعداد وتأهيل أدوات التطوير المحلية في الجولة القادمة للبدء في **المهمة 03 (إثبات قاعدة وقنوات P0)** و**المهمة BK02 (تجربة أداة النسخ وPITR)**، مع الحفاظ التام على بيئة الجهاز القائمة وتجنب أي كسر أو استبدال للمشاريع الأخرى للمستخدم.

---

## 2. فحوص القراءة الاستكشافية لتشخيص نقص Flutter

قبل الشروع في أي إصلاح، تُنفذ الفحوص التالية (قراءة واستعلام فقط دون كتابة) لتحديد السبب الجذري لغياب الملف `dart.exe` من المسار `C:\flutter\bin\cache\dart-sdk\bin`:

1. **فحص مستودع Git لـ Flutter**:
   - التحقق مما إذا كان المجلد `C:\flutter` مستودع Git أصليًا عبر الاستعلام:
     ```powershell
     git -C "C:\flutter" status --short
     git -C "C:\flutter" branch -v
     git -C "C:\flutter" remote -v
     ```
   - *الهدف*: معرفة الفرع المثبت (stable / beta) وهل توجد ملفات متضاربة أو كاش تالف أثناء تحديث سابق.
2. **فحص سجلات مكافحة الفيروسات (Antivirus Quarantine)**:
   - فحص سجل الحماية في Windows Defender للتأكد هل تم حظر أو عزل `dart.exe` نتيجة اشتباه كاذب:
     ```powershell
     Get-MpThreatDetection | Select-Object -First 5 ThreatName, Resources
     ```
   - *الهدف*: التأكد من أن المشكلة ليست حظرًا أمنيًا نشطًا يحذف الملف فور إعادة تنزيله.
3. **فحص أذونات المجلد (Permissions & ACLs)**:
   - فحص أذونات القراءة والتنفيذ للمستخدم الحالي على مسار الكاش:
     ```powershell
     Get-Acl "C:\flutter\bin\cache" | Format-List
     ```
4. **فحص أقفال العمليات (Lockfiles)**:
   - فحص وجود ملفات أقفال متبقية من محاولات سابقة مثل `flutter.bat.lock` والتأكد من عدم وجود عملية أخرى تستخدم المجلد.

## 3. اقتراح إصلاح Flutter مع حماية المشاريع القائمة

لضمان عدم التأثير على أي مشاريع أخرى قد تكون مرتبطة بالتثبيت الحالي في `C:\flutter`:

- **المسار الأساسي (إصلاح الكاش في موضعه)**:
  - إذا أثبت الفحص أن `C:\flutter` سليم وقابل للتحديث، يُنفذ أمر استعادة الكاش الرسمي المعتمد من Flutter دون مساس بالملفات العامة:
    ```powershell
    & "C:\flutter\bin\flutter.bat" precache
    ```
  - ثم فحص النتيجة عبر:
    ```powershell
    & "C:\flutter\bin\flutter.bat" doctor -v
    ```
- **المسار الاحتياطي (في حال تعذر إصلاح المسار القائم)**:
  - إذا كان التثبيت في `C:\flutter` مقفلاً أو مخصصًا لبيئة قديمة لا يرغب المستخدم في تحديثها:
    - يُقترح تنزيل حزمة Flutter مستقرة (Stable SDK) في مسار مخصص ومعزول للمشروع (مثل `C:\tools\flutter_maqtoop`).
    - يتم ضبط المسار داخل **جلسة PowerShell الحالية فقط** (`$env:PATH = "C:\tools\flutter_maqtoop\bin;" + $env:PATH`) دون تعديل متغيرات البيئة العامة للنظام.

## 4. اقتراح تشغيل PostgreSQL معزول للتجارب عبر Docker

الجهاز يحتوي على `Docker version 29.1.3` ومحرك WSL 2 مثبت مسبقًا، وتفاديًا لأي تعارض مع بيانات أو مشاريع المستخدم القائمة:

### إجراءات الحماية قبل التشغيل
1. استعلام وفحص الحاويات والمجلدات القائمة لضمان عدم المساس بها:
   ```powershell
   docker ps -a
   docker volume ls
   ```
2. فحص المنفذ `5432`؛ إذا كان مستخدمًا بواسطة خدمة أخرى، يُخصص المنفذ `5433` للحاوية لتفادي أي تضارب شبكي:
   ```powershell
   Test-NetConnection -ComputerName localhost -Port 5432
   ```

### مواصفات الحاوية المقترحة لمقطوب
- **اسم الحاوية**: `maqtoop-dev-postgres` (فريد ومحدد).
- **الصورة**: `postgres:16-alpine` (خفيفة ومطابقة لنسخة PostgreSQL 16 المذكورة بالدليل).
- **المجلد المستقل (Isolated Volume)**: `maqtoop_pg_dev_data` (معزول تمامًا عن أي قواعد أخرى).
- **بيانات الاتصال التجريبية**:
  - المستخدم: `maqtoop_dev`
  - قاعدة البيانات: `maqtoop_dev_db`
  - كلمة المرور: تعين محليًا لبيئة التطوير (لا تستخدم في الإنتاج).
- **أمر التشغيل المقترح للمراجعة**:
  ```powershell
  docker run -d `
    --name maqtoop-dev-postgres `
    -p 5432:5432 `
    -e POSTGRES_USER=maqtoop_dev `
    -e POSTGRES_PASSWORD=maqtoop_dev_pass `
    -e POSTGRES_DB=maqtoop_dev_db `
    -v maqtoop_pg_dev_data:/var/lib/postgresql/data `
    postgres:16-alpine
  ```

## 5. جدول الأدوات المطلوب تنزيلها ومكانها وأثرها

| الأداة / الحزمة | مكان التنزيل والتخزين | الحجم التقديري | الأثر على بيئة الجهاز ونظام التشغيل |
|---|---|---|---|
| **صورة Docker (`postgres:16-alpine`)** | مخزن صور Docker Desktop (داخل قرص WSL الافتراضي) | ~150 ميجابايت | معزولة داخل Docker؛ لا تلمس ملفات نظام Windows أو السجل (Registry). |
| **كاش Dart SDK المفقود** | داخل مجلد `C:\flutter\bin\cache\dart-sdk\` | ~200 ميجابايت | محصور بالكامل داخل مجلد Flutter ولا يؤثر على أي مجلد آخر. |
| **صورة الحاوية وملحقات التجربة** | مجلد Docker Volume (`maqtoop_pg_dev_data`) | ينمو حسب تجارب الاختبار | معزول بالكامل وقابل للحذف بأمر واحد. |

*لا تتطلب الخطة تنزيل SDKs عملاقة جديدة أو تثبيت خدمات نظام دائمة في Windows.*

## 6. معايير القبول المنفصلة (Separated Acceptance Gates)

تُفصل معايير القبول في الجولة القادمة إلى ثلاث بوابات مستقلة لضمان عدم الخلط بين الجاهزية التشغيلية:

### البوابة 1: تشغيل الأدوات الأساسية (Tool Execution Gate)
- نجاح خروج الأوامر التالية برموز نجاح (Exit code 0):
  ```powershell
  flutter --version
  dart --version
  docker ps
  ```
- معيار النجاح: ظهور رقم إصدار Dart ورقم إصدار Flutter دون أي خطأ فقدان للملفات التنفيذية.

### البوابة 2: التحقق من سلاسل البناء التجريبية (Build Verification Gate)
- إنشاء مجلد تجريبي مؤقت ومستقل (خارج مجلدات الإنتاج) وفحص سلاسل البناء:
  - **تجربة Android**: بناء حزمة تجريبية أولية للتأكد من توافق `ANDROID_HOME` وJDK 17 وأدوات Gradle:
    ```powershell
    flutter build apk --debug
    ```
  - **تجربة Windows Desktop**: بناء ملف تنفيذي تجريبي للتأكد من استدعاء أدوات Visual Studio 2022 C++ وCMake:
    ```powershell
    flutter build windows --debug
    ```
- معيار النجاح: اكتمال عملية البناء وتوليد الملف التجريبي دون أخطاء فقدان أدوات المترجم.

### البوابة 3: فحص الاتصال بقاعدة البيانات (Database Connectivity Gate)
- فحص استجابة حاوية PostgreSQL واستقبالها لاستعلام الاتصال الأولي.

## 7. التمييز الصريح بين نجاح `SELECT 1;` وقبول المعاملات

> **تحذير هندسي صارم**:\
> نجاح تنفيذ استعلام `SELECT 1;` يثبت فقط **الاتصال الشبكي بالمنفذ واستجابة المحرك الأساسي**؛\
> **ولا يثبت إطلاقًا الجاهزية التشغيلية أو المعمارية للنظام**.

### ما الذي يحتاج أدلة مستقلة ولا يثبته `SELECT 1;`؟
1. **عزل المنشآت المتعددة (RLS)**: يحتاج فحص سياسات الأمان بدور التطبيق المحدود والتأكد من رفض الوصول المتقاطع.
2. **منع البيع المزدوج والتزامن**: يحتاج تجربة إرسال معاملتين متزامنتين على آخر قطعة وفحص سلوك أقفال الصفوف (`SELECT ... FOR UPDATE`).
3. **أرشفة WAL والاستعادة لنقطة زمنية (PITR)**: يحتاج تنفيذ تجارب الاستعادة المعزولة (BK02 وV-BK01) وقياس RPO وRTO بدقة.
4. **التوافق المالي**: يحتاج التحقق من نوع الحقول وحسابات الكسور ودقة القيود المحاسبية.

## 8. احتياج iOS إلى بيئة macOS لاحقًا

- **الحقيقة الهندسية الصارمة**:\
  بناء واختبار تطبيقات العميل والتاجر لنظام **iOS** يتطلب بيئة تشغيل **macOS**، وأدوات **Xcode**، وشهادات توقيع أبل، ومكتبات CocoaPods.
- **الحدود على الجهاز الحالي**:\
  نظام التشغيل الحالي هو **Windows 10**، ومن المستحيل هندسيًا بناء أو محاكاة أو تشغيل اختبارات أصلية لنظام iOS عليه.
- **المسار المعتمد مستقبلاً**:\
  يؤجل التحقق من بناء iOS إلى مرحلة توفير عداء مخصص لنظام macOS في GitHub Actions (`macos-latest`) أو استخدام جهاز Mac مستقل مخصص للاختبارات عند بدء الدفعة المخصصة لنظام iOS. لا يجوز ادعاء جاهزية iOS محليًا على هذا الجهاز.

## 9. خطة التراجع (Rollback Plan)

في حال حدوث أي عائق أو رغبة المستخدم في إرجاع الجهاز لحالته السابقة تمامًا بعد التجارب:

1. **إزالة حاوية وبيانات PostgreSQL المعزولة**:
   ```powershell
   docker stop maqtoop-dev-postgres
   docker rm maqtoop-dev-postgres
   docker volume rm maqtoop_pg_dev_data
   ```
   *النتيجة*: حذف الحاوية والبيانات التجريبية بالكامل دون المساس بأي حاويات أو بيانات أخرى في Docker Desktop.
2. **استعادة حالة كاش Flutter**:
   - الاحتفاظ بنسخة مضغوطة من مجلد `C:\flutter\bin\cache` قبل بدء الإصلاح.
   - في حال تعثر الإصلاح، يمكن حذف الكاش المستحدث واستعادة الحالة السابقة فورًا.
3. **مسارات الجلسة المؤقتة**:
   - كافة متغيرات PATH المعدلة تجرى داخل جلسة PowerShell المؤقتة؛ وبمجرد إغلاق نافذة الطرفية، تعود متغيرات بيئة Windows العامة كما كانت دون أي أثر دائم.
