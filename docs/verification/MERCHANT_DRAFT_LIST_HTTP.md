## دليل الاختبار

أضيف اختبار merchant-drafts-list-http إلى المجموعة الحالية دون حذف حالة سابقة. بدأ PostgreSQL الحقيقي، وفشل GET القائمة404 قبل التنفيذ، ثم نجح بعد إضافة المسار والترحيلة. يعتمد على خادم HTTP فعلي وحسابات LOGIN محدودة مستقلة من fixture catalog_drafts.cjs؛ مشغل القاعدة يستخدم لإنشاء بيانات الحجم ومراقبة الأقفال والمقارنة فقط.

الحالة تختبر:

- إنشاء ثلاث مسودات عبر HTTP، وتهيئة130 مسودة إضافية للتاجر على فرعين عبر SQL لتجربة الحجم والحالات والوقت المتساوي. توليد SQL fixture ليس ادعاء إنشاء كل هذه المسودات عبر HTTP؛ مسار الإنشاء الاعتيادي مختبر منفصلًا.
- إرجاع133 مسودة في8صفحات عندlimit=17 دون معرف مكرر أو مفقود، بترتيبcreated_at/id ثابت حتى مع دقة وقت متساوية. القيمة الافتراضية50، وتجاوز100 أو حجم غير صحيح يرفض400.
- إخفاء9 مسودات للتاجر في فرع غير مخول، و3 مسودات لمستخدم آخر من المنشأة نفسها، و4 لتاجر آخر. كل حساب يرى المجموعة المحددة له فقط؛ branchId صريح غير مخول أو خارج المنشأة403.
- التصفية بكل الحالات الخمس والفرع، وجمع التصفية مع البحث، والبحث بالماركة والموديل دون حساسية حالة أحرفASCII، والبحث العربي، واعتبار% و_ والشرطة العكسية حروفًا فعلية.
- رفض دور الإدارة والعميل والمندوب والخدمة403، والطلب دون جلسة401؛ لا اختيار منشأة أو دور من الاستعلام.
- رفض الاستعلامات الزائدة والمكررة وq أطول من100حرف والحالة غير المعتمدة ومؤشر غير صالح والتاريخ الفاسد400. تغيير الحساب أو البحث أو الحالة أو حجم الصفحة مع المؤشر السابق مرفوض400.
- سحب فرع سجل الارتكاز عبر API ثم متابعة القائمة غير المقيدة بذلك الفرع بالمؤشر نفسه: ينجح200 ولا يعيد الفرع المسحوب. المؤشر لا يعتمد على جلب السجل السابق ولا يمثل تفويضًا.
- الإدارة تأخذ قفل السحب ويوقفها hook اختباري قبلCOMMIT. يبدأ طلبا قائمة غير مقيدة وطلب branchId صريح، وتثبت pg_blocking_pids أن كليهما ينتظران جلسة الإدارة. بعد تثبيت السحب تخفي القائمة الفرع، ويرفض طلبه الصريح403. عند سحب جميع الفروع ترجع القائمة فارغة.
- جلسة قراءة تنتظر قفل تفويض الفرع، ثم يسجل التاجر logout-all عبرHTTP. بعد تحرير القفل ترفض الجلسة القديمة401 وتنجح جلسة دخول جديدة؛ لا اعتبار فحص المصادقة الأول تفويضًا دائمًا.
- مقارنة جميع صفوف المسودات والنسخ قبل القراءات وبعدها تثبت عدم وجود كتابة من GET. مقارنة بيانات الشراء الموجودة في fixture تثبت تطابق المخزون والعروض والأهلية والطلبات والمستحقات والقيود قبل وبعد المهمة.
- فشل ترحيلة merchant_draft_list.sql قبلCOMMIT بخطأ مصطنع يزيل الدالة والفهرس ويحفظ البيانات السابقة. الترحيلة السليمة تضيفهما دون تغيير بيانات شراء. ليست هذه تجربة نسخ أوPITR أو إنتاج.
