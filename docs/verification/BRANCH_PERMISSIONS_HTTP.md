## الدليل الفعلي

بدأ اختبار GET الإداري على PostgreSQL الحقيقي بخروج فاشل404 بدل200 قبل التنفيذ. بعد إضافة المسارات والترحيلة نجحت حالات branch-permissions-http وbranch-permissions-reply-before وbranch-permissions-reply-after، بخادم HTTP على loopback ومحرك PostgreSQL16.16 معزول وقاعدة جديدة لكل حالة. حسابات LOGIN مستقلة ومحدودة؛ صاحب قاعدة الاختبار يستخدم للتهيئة ورصد الأقفال والمقارنة فقط، لا لتنفيذ إجراءات الإدارة والتاجر محل القبول.

تثبت الحالات ما يلي:

- العرض والمنح والسحب إداري فقط، وعزل فروع التاجر عن منشأة أخرى403؛ الحساب/الفرع المفقود404، الحساب غير التجاري409، والحقول الزائدة والمدخلات غير الصالحة400. منح حساب موقوف409.
- طلبا منح بنفس المفتاح يعيدان نتيجة واحدة/v1، وتغير السبب بنفس المفتاح409. بعد سحب v2، إعادة نتيجة المنح القديمة لا تغير inactive/v2، والمنح بمفتاح جديد ونسخة قديمة409. المنح الصريح بالنسخة الحالية ينجح.
- اتصال مستقل يمسك صف المسودة FOR UPDATE، ويرصد الاختبار طلب submit منتظرًا عبر pg_blocking_pids. تسحب الإدارة الفرع عبر HTTP قبل تحرير القفل. يرفض طلب التاجر403 وتبقى صفوف المسودة مطابقة؛ لا request_result ولا audit_event لذلك الطلب. إعادة طلب إنشاء مخزن وقراءة المسودة بعد السحب ترفضان403 أيضًا.
- رفع PNG ينجح في الفحص المسبق ثم ينتظر قفل التكرار المرصود. تسحب الإدارة الفرع عبر HTTP، ثم يحرر القفل: النتيجة403 دون media_asset أو نتيجة طلب جديدة. الفحص المسبق ليس تفويضًا دائمًا.
- grant وrevoke مختلفان بنفس expectedVersion يتنافسان بقفل مرصود: واحد200 والآخر409 وتزيد النسخة مرة واحدة.
- طلب إداري ينتظر قفل الحساب/الفرع؛ مدير آخر يوقف حساب المدير الأول ويعيد تفعيله عبر HTTP. بعد تحرير القفل ترفض جلسته القديمة401، ولا تتغير نسخة الصلاحية. تسجيل دخول جديد يعيد صلاحية الإدارة الحالية.
- فقد الرد قبل COMMIT يعيد المعاملة بلا زيادة النسخة؛ وبعد COMMIT تحفظ الزيادة. يعاد الطلب نفسه بالتوازي مرتين: نتيجة واحدة متطابقة ونسخة واحدة وسجل تدقيق واحد بالمفتاح.
- القائمة تتصفح107 فروع في صفحتين، دون تكرار أو إدخال فرع المنشأة الأخرى. SQL المولد للصفحات fixture فقط؛ لا توجد ميزة إنشاء فرع عبر API في هذه المهمة.
- التاجر لا يستطيع SELECT/UPDATE جدول التفويض أو قراءة سجل تدقيقه مباشرة. حذف سجل تدقيق حتى بدور مشغل الاختبار يرفضه trigger الثبات23514. الدوال لا تمنح إلى PUBLIC.
- الترحيلة الفاشلة بخطأ مصطنع قبل COMMIT تزيل إضافاتها وتحفظ صف التفويض السابق. الترحيلة السليمة تحفظ الصف active=true/version=1؛ تطابق بيانات الشراء محفوظ في الحالتين.

تبقى sku/stock/offer/quote/hold/payment/purchase_order/order_item/payable/journal/posting وeligible_offer مطابقة قبل وبعد الحالات. لا approved، وapprove يظل409 وقائمة العميل فارغة مع publicationEnabled=false. تغطي الحالات عمليات كتالوج التاجر، ولا تثبت صلاحيات كل وظيفة مستقبلية في المنصة.

## سجل التنفيذ والمراجعة

Ruling: إعادة استخدام معاملة ومسارات catalog خلف catalog.enabled بدل خدمة منفصلة — النطاق هو تفويض فروع المسودات القائم، ولا تبعيات جديدة. سلطة الإدارة مفروضة داخل PostgreSQL حتى عند منح EXECUTE لدور غير إداري عمدًا للاختبار.

Ruling: صف التفويض المسحوب يبقى inactive مع version — تجنب عودة النسخة0 وإعادة منح قديمة بعد حذف الصف. استجابة منع التكرار تمثل الأمر الأصلي؛ القائمة تمثل الحالة الحالية.

المراجعة المستقلة لم تجد تجاوز تفويض مؤكدًا، ووجدت اختلاف404/403 للفرع المفقود. عولج فصل الوجود عن ملكية المنشأة وأضيف اختبار grant وrevoke للمفقود. أكدت إعادة المراجعة معالجة الملاحظة وعدم بقاء ملاحظاتP1/P2 مؤكدة. لا تفويض دمج أو نشر ضمن هذا التنفيذ.
