# تحقق HTTP لأول شراء — 26 نوفمبر 2026

النطاق R02 وR03 وR05 وR09 وR10 وR15. نُفذ العقد في [خادم HTTP](../../backend/server.mjs)، وتدعمه [ترحيلة HTTP](../../db/first_purchase/http.sql) بعد مخطط الشراء ودوال صلاحياته.

## المسار المجرّب

يشغّل [اختبار HTTP](../../db/first_purchase/http.cjs) خادم API ومزود دفع مصطنعًا على loopback، ويرسل طلبات HTTP فعلية. لكل هوية LOGIN محدود وجلسة عشوائية تحفظ بصمتها. إشعارات الدفع وإثباتات التسليم والبيانات مصطنعة.

| الحالة | التحقق |
|---|---|
| عرض السعر والحجز | ينشئ العميل عرضًا ثم حجزًا، من قائمة عروض مؤهلة مجهزة على الخادم. |
| طلبا الدفع | طلبان بمفتاحين مختلفين مع انتظار قفل مرصود داخل PostgreSQL يعيدان attemptId واحدًا وOutbox واحدة لهذا الشراء. |
| فقد رد API | قبل COMMIT تتراجع نية الدفع وتنجح إعادة المفتاح. بعد COMMIT تعود نفس النتيجة في الدفع والاسترداد والبديل والتسليم. |
| فقد رد قبول المزود | يعاد إرسال نفس providerKey بعد انتهاء الإيجار وتظل عملية التحصيل لدى المزود المصطنع واحدة. |
| توقيع الإشعار وتكراره | يرفض التوقيع الخاطئ، ويقبل تكرار الحدث وحدثًا جديدًا لنفس التحصيل دون قيد زائد. |
| فقد إشعار المزود | unknown تبقي المحاولة النشطة، ثم يثبت استعلام موقّع نجاح التحصيل دون أمر خصم جديد. |
| سلامة المطابقة | يرفض فشلًا بتوقيع خاطئ أو مفتاح عملية مختلف. الفشل النهائي الموثق يتيح محاولة جديدة. |
| التسليم والمستحق | مندوب مكلف وإثباتا pickup وdelivered صحيحان. يعاد delivered بعد فقد الرد دون مستحق إضافي. قيمة المثال 54,000 والمستحق 48,600. |
| التحصيل المتأخر | تحرير قطعة ثم تخصيصها لآخر، وتسجيل دفعة المتأخر في 2113 واستردادها عبر HTTP مرة واحدة. |
| البديل | بديل بنفس المبلغ، وإعادة الطلب بعد فقد الرد تعيد نفس الطلب مع قطعة واحدة ودون تحصيل جديد. |
| الخصوصية والجلسة | رفض طلب الغير وحجب المورد والتكلفة والعمولة ورفض إعادة نتيجة مخزنة بجلسة ملغاة. |
| بيانات سابقة | تثبت ترحيلة HTTP فوق مخطط فيه عرض سابق، ويتحقق بقاء بياناته وبدء المعرفات الجديدة بعده. |

النتائج الفعلية في [results.json](../../db/first_purchase/results.json). لكل حالة قاعدة مستقلة UTF-8، وتغلق خدمات HTTP ومحرك PostgreSQL في النهاية.

## التشغيل وحدود القبول

استخدم التنفيذ Node.js HTTP وnode-postgres، وربط الهوية باتصالات LOGIN المحدودة امتدادًا للتجربة السابقة. التشغيل المستقل يستخدم ملف إعداد خاصًا خارج Git. التفاصيل في [دليل backend](../../backend/README.md).

تثبت ترحيلة HTTP مرة واحدة بعد schema.sql وsecurity.sql، وتضيف الجلسات ونيات الدفع وOutbox وIdempotency والقراءات المحدودة دون حذف سجلات الشراء السابقة. اعتماديات المحرك المحمول تخص الاختبارات، واعتماد الخادم الجاري مستقل عنها.

النتيجة تخص أول هاتف بكمية واحدة وتسليم كامل داخل صنعاء وبديل بنفس المبلغ. تجهز هويات التجربة والعناوين والتكليفات وقائمة العروض المؤهلة مسبقًا. مزود السداد الفعلي وتسجيل الحسابات العام وتطبيق Flutter تتبع مهام تكاملها. فشل رد المال عند المزود يبقى مسجلًا للمتابعة بقرار الاسترداد ومفتاحه الأصلي.

نتيجة التشغيل النهائية: 56/56 حالة ناجحة على PostgreSQL 16.16. أُغلقت ملاحظات المراجعة المستقلة، بما فيها مطابقة التحصيل عند فقد الإشعار وتوثيق جميع حالات المزود بتوقيع مرتبط بمفتاح العملية.

سباق القرارين عبر HTTP: جرب http.cjs الاسترداد والبديل من طلبين متداخلين بمفتاحين مختلفين، مع رصد انتظار قفل الدفعة في PostgreSQL. عند تقديم الاسترداد عاد202 والبديل409، وعند تقديم البديل عاد200 والاسترداد409. تحقق قيد تسوية واحد بمبلغ54,000 لكل دفعة، وصفر في2113 بعد التسوية، وبقاء قيود طلب المشتري الآخر مطابقة ومستحقه48,600. نجح التشغيل الكامل56/56.
